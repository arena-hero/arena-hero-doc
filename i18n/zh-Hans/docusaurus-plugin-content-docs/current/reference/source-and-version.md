## 权威性

本仓库是面向读者的官方游戏规则与游戏 API 规范。服务器代码、数据库约束和自动化测试
执行真实运行时契约。

如果已发布文字与已发布实现不一致：

1. 不要把差异当作隐含规则加以利用；
2. 记录准确的服务器版本和观察到的行为；
3. 在文档或服务器仓库提交 Issue；
4. 决定预期行为后同时更新两个仓库。

## 兼容性边界

以下是协议级行为，修改时必须明确决定契约版本：

- 15 秒全局命令窗口，以及以 `state` 为动作触发器；
- 确定性结算阶段和原子提交；
- 完整来源计划替换与 Manual 优先级；
- 严格动作联合与幂等；
- WebSocket 消息类型和重连快照；
- 战争迷雾隐私边界；
- 地图生成器契约；
- 决定可重放结果的核心平衡规则。

文字、布局、图表、示例和解释顺序可以改进，而不改变游戏契约。

## 版本策略

公开 API 仍为 v0.1 时暂不启用 Docusaurus 多版本快照。网站以两种镜像语言发布一份
`Current` 契约。宣布第一个稳定兼容版本后，可以把此前契约冻结为 Docusaurus 版本。

## 更新契约

一次游戏玩法或游戏 API 修改只有同时包含以下内容才算完成：

- 服务器仓库中的实现和测试；
- 本仓库中同步更新的英文与简体中文页面；
- 适用时更新 OpenAPI 或 AsyncAPI Schema；
- 通过验证的双语生产构建；
- 现有客户端可能中断时给出明确兼容性说明。
