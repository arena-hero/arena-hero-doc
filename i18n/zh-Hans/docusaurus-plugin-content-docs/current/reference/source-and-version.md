## 文档和服务端不一致时

这些页面描述公开游戏规则和 API。实际运行行为由服务端代码、数据库约束和测试决定。

如果已发布文字与已发布实现不一致：

1. 不要把差异当作隐含规则加以利用；
2. 记录准确的服务器版本和观察到的行为；
3. 在文档或服务器仓库提交 Issue；
4. 决定预期行为后同时更新两个仓库。

## 哪些修改会影响兼容性

修改以下内容可能破坏现有客户端，需要明确决定协议版本：

- 15 秒全局命令窗口，以及以 `state` 为动作触发器；
- 确定性结算阶段和原子提交；
- 完整来源计划替换与 Manual 优先级；
- 动作字段规则与幂等；
- WebSocket 消息类型和重连快照；
- 战争迷雾隐私边界；
- 地图生成器契约；
- 决定可重放结果的核心平衡规则。

文字、布局、图表、示例和解释顺序可以改进，而不改变游戏契约。

## 为什么现在没有版本选择器

公开 API 仍是 v0.1，所以网站目前只发布一个版本，提供英文和简体中文。第一个稳定兼容
版本发布后，可以把旧协议保留为 Docusaurus 版本。

## 修改协议时要更新什么

修改游戏玩法或游戏 API 时，需要同时更新：

- 服务器仓库中的实现和测试；
- 本仓库中同步更新的英文与简体中文页面；
- 适用时更新 OpenAPI 或 AsyncAPI Schema；
- 通过验证的双语生产构建；
- 现有客户端可能中断时给出明确兼容性说明。
